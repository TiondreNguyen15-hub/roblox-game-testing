## Test scope

Core tests exercise config round-trips/overwrites, malformed/unsupported/non-finite input rejection, unchanged state on load failure, bounds, projection/near-plane rejection, animation and entity invariants. Visual tests generate real ImGui draw lists and exercise filters and corner/overlay settings. Menu tests generate each tab, fade-out frames and validate CPU/uptime bounds. Renderer/system/menu translation units also compile for Windows.

The included Windows workflow builds with Visual Studio 2022, runs CTest, then runs --smoke-test using DX11 WARP. Inspect the Actions run for its actual result; merely including the workflow does not establish runtime success.

## Remaining runtime checks

This Linux build host has no Windows desktop or Wine, so local tests do not establish Windows rendering, hardware GPU behavior or device-loss recovery. Confirm on Windows 10/11:

1. Normal hardware and --warp startup; --smoke-test exits 0 and produces smoke-result.txt.
2. Insert toggle, sidebar keyboard/mouse navigation, every visual filter and rendering control.
3. Save/relaunch/load/defaults, invalid config warning, unwritable configuration errors.
4. Window resize, 100/150/200% DPI, minimize/restore, full occlusion and F10/window close.
5. GPU/CPU/system metrics under load and stable memory over a 10-minute run.
6. Hardware-specific FPS with VSync on/off and entity count 1/64. No universal FPS guarantee or GPU-utilization measurement is claimed.

Device removal is handled by reporting HRESULT, releasing resources and exiting; automatic device recreation is not implemented. There are no unfinished placeholder APIs. The simulation is deterministic generated data, not an actual game's telemetry.
