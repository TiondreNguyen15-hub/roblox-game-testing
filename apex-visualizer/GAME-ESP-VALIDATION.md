The private Roblox file is 12,238,232 bytes; SHA256 `ee35521f98659767d1cb3f1215a88c920980709fb891a1327cc9dd13666d7d7d`. It has FP32 `images` [1,3,640,640] -> `output0` [1,5,8400], opset 19, with literal metadata label Enemy. The adapter uses standard RGB/[0,1]/gray114 letterboxing and single-class YOLO pixel-coordinate output. No metadata is executed. Candidate filtering examines all rows, selects at most 1000 before IoU NMS and returns at most 300. Labeled footage is still needed to establish detection accuracy for a specific Roblox experience.

Apex remains primary/default at startup, using its existing 416px/300x6 decoder and enemy-settings.json. Roblox uses roblox-enemy-settings.json. Switching saves the previous profile, clears old detection state and disables analysis until re-enabled or a model is browsed. Private weights and their Drive links are not redistributed. The source fixtures are explicitly synthetic and remain outside runtime/models.

The user previously supplied a CPU-only-runtime diagnostic. The combined launcher can install the existing pinned GPU runtime into the exact running app folder, then update it. Installation is not proof of CUDA inference. The user also reported that the combined launcher did not reopen the app, but no final console/error text was supplied; the original PC exit cause is unresolved. The launcher now avoids an intermediate reopen/close and verifies the final GUI window stays alive for 1.5 seconds. Early failure includes exit details and an own-app log/crash report in launch-failure.txt. This is a startup check, not a guarantee against later model/driver failures.

The GPU installer retains its existing pinned dependency installer. It now accepts explicit TargetExe/NoLaunch options for the combined workflow; standalone repair still starts the app with verification. New launch-app.ps1 is shared by the updater and repair helper. The startup workflow tests these changes without pretending hosted Windows has an RTX GPU. No performance improvement or user-PC installation success is asserted.

Changes: profile enum and bounded preprocessing/YOLO decoder, isolated settings, adapter dispatch using the existing ORT CPU/CUDA loader, profile UI/CLI, synthetic native integration fixture, decoder/settings tests and startup-verification scripts. Existing renderer, live preview, optional exact frame, click-through overlay/F8, OBS, old OCR tools and other settings remain. No game memory access, injection, anti-cheat bypass or automated gameplay is added.
